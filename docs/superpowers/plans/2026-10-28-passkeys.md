# Passkeys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let members create a passkey right after their first email sign-in on a device, then sign in with Face ID / fingerprint on the website and in the native app, and manage their keys in Settings.

**Architecture:** WebAuthn on the API with `@simplewebauthn/server`, single-use challenges stored in the DB, credentials in `passkey_credentials`; a passkey sign-in activates the device through `activateDeviceForUser` like the email link/code. The app has one `passkeyService` with a web implementation (`@simplewebauthn/browser`) and a native one (`react-native-passkey`), used by the sign-in screens, a new invitation screen and a Settings section.

**Tech Stack:** Hono/Bun/Drizzle/Vitest (API, two repos: padmakara-api and padmakara-app), Expo Router/React Native/Jest+RTL (app), `@simplewebauthn/server@14`, `@simplewebauthn/browser@14`, `react-native-passkey@3.6`.

**Spec:** `padmakara-api/docs/superpowers/specs/2026-10-28-passkeys-design.md` (read it first; copy is fixed there).
